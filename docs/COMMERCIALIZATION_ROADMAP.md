# Liberty Cats 商业化与制造 Roadmap

版本：2026-07-31  
适用目标：把版本化、确定性的 Liberty Cats 角色系统发展为可商用的数字角色平台，并能稳定输出供工厂打样、3D 打印、小批量生产和后续开模量产使用的制造资产。

## 1. 结论

当前项目已经具备可靠的“角色配置与数字资产内核”，但还不具备“工厂可直接生产”的完整制造能力。

现阶段可以把同一 Token 稳定生成、预览和导出为 GLB；不能把现有 GLB 直接等同于可打印生产文件。制造资产需要经过独立的实体化、加厚、合并/拆件、比例、公差、稳定性和 DFM（Design for Manufacturing）检查。

推荐把产品拆成三个共享 `CatTraits`、但验收标准不同的产物：

```text
CatTraits（唯一角色事实源）
├─ Realtime Asset：网页、游戏、AR/VR、动画 GLB
├─ Render Asset：宣传图、视频、角色卡、高质量渲染
└─ Manufacturing Asset：实体化网格、拆件、连接结构、3MF/STL/STEP 和工厂工艺包
```

必须避免用一套网格同时承担实时动画、视觉渲染和实体制造。三类资产可以同源生成，但需要不同的几何处理和质量门禁。

## 2. 当前项目盘点

### 2.1 已完成：可作为商业化基础保留

| 能力 | 当前证据 | 商业价值 |
|---|---|---|
| 版本化角色合同 | `CatTraits` 包含 schema/generator 版本、seed、Trait、形态和身份 | 可追溯、可重新生成 |
| 确定性生成 | 相同输入产生相同配置和模型，锁定参数可生成变体 | 支持订单复现和售后补件 |
| 全量 Token catalog | 9,901 条有效记录，2 条异常有明确排除规则 | 可建立 Token 到商品 SKU 的映射 |
| 纯角色工厂 | `createCatAssembly()` 不依赖 Vue/DOM | 可迁移到 CLI、服务器和批处理 |
| 程序化角色组件 | 身体、耳、尾、四肢、面部、毛色、装备均已模块化 | 为制造版重建提供语义部件 |
| 稳定部件与 socket | 注册表、关节、装备挂点有自动测试 | 可用于拆件、定位销和配件体系 |
| 数字 GLB 导出 | PBR 转换、动画、metadata 和 Three.js 回读 | 可交付游戏与 DCC 数字资产 |
| 角色级输出 | PNG、透明头像、三/四视图、角色卡、JSON、分享链接 | 已形成基础商品展示物料 |
| 全量自动审计 | 9,901 normalized/assembled/rendered/metadataMatched，当前摘要为 0 结构失败 | 有批量生产质量门禁基础 |
| 代表集 | 133 个代表 Token、2,322 个 Trait 组合簇 | 可扩展成人工艺术验收集 |
| 基础 Blender 检查 | 已有 GLB 导入、动画和 `.blend` 保存脚本 | 可扩展为制造网格检查 CLI |

### 2.2 部分完成：不能按“已商用”验收

| 能力 | 当前状态 | 尚缺 |
|---|---|---|
| 44 个 Trait 视觉覆盖 | 有独立配方、代表 Token 和审计 | manifest 中 44 项仍全部为 `pending-visual-verification`；缺少签字式人工验收 |
| 2D→3D 忠实度 | 有原图对照和固定视角 | 缺少量化评分、差异归因、艺术总监批准和版本冻结 |
| GLB DCC 兼容 | Three.js 回读完整，已有 Blender 脚本 | 缺少持续集成中的真实 Blender 批量验证；Unity/Unreal 结论目前主要是结构推断 |
| 版本管理 | 有 schemaVersion 和 generatorVersion | `assetVersion`、`manufacturingProfileVersion`、迁移/弃用策略尚未落地 |
| 质量基线 | 有三角面、材质、画布和边界检查 | 是实时资产预算，不是打印/注塑 DFM 预算 |
| 商业前端 | 编辑、浏览和导出功能丰富 | 账号、订单、支付、队列、资产存储、授权、水印、审计日志和客服后台未建立 |
| 原图分发 | 远程优先、本地 fallback | 生产 CDN、缓存、版权授权和失效处理尚未冻结 |
| Special | 有 7 类场景配方和覆盖合同 | 需决定哪些是“角色商品”、哪些是“情景摆件”，不能共用同一制造策略 |
| 小游戏 | Crossy 技术原型存在 | 尚未成为当前商业闭环，不应阻塞制造 MVP |

### 2.3 未完成：工厂交付前的硬性缺口

1. 没有 `ManufacturingProfile`：成品高度、单位、工艺、材料、颜色模式、最小壁厚、最小特征、间隙、底座和拆件规则尚无版本化合同。
2. 没有 Print Assembly：当前角色是渲染/动画节点树，不是制造用封闭实体。
3. 没有 watertight/manifold、自交、法线、退化面、孤立壳体和内部不可见几何门禁。
4. 没有将相交部件做稳定布尔并集，或转换为明确可装配零件的流程。
5. 没有最小壁厚、最小柱径、尖端、孔径和浮空细节检查。
6. 没有实体比例、真实单位、目标高度和供应商公差的端到端验证。
7. 没有面向运输和站立稳定性的重心、接地面积、底座与跌落风险设计。
8. 没有配件拆分、定位销、榫槽、磁铁孔、胶合面、防呆和装配顺序。
9. 没有支撑方向、排液孔、空心化、树脂困液和后处理可达性设计。
10. 没有 3MF/STL 制造导出；GLB 应继续服务数字资产，不应作为唯一工厂主文件。
11. 没有 BOM、颜色/材料表、零件号、缩略图、版本、校验和及装配说明组成的工厂交付包。
12. 没有实际打印 coupon、黄金样件、供应商 DFM 回签和批次 QA。
13. 没有订单到生成、人工复核、冻结、交厂、返工和补件的生产状态机。
14. 没有明确的 IP、NFT 持有者商业使用权、第三方参考代码/素材许可及用户生成内容条款。

## 3. 建议修改的项目结构

建议保留现有实时角色管线，并新增制造域，不在 `exportCharacterGlb.js` 中继续堆打印逻辑。

```text
src/
  core/
    CatTraits                       # 保持唯一角色事实源
  manufacturing/
    ManufacturingProfile.js        # 工艺、尺寸、材料、公差、颜色与版本
    createPrintAssembly.js          # 从角色语义部件生成制造装配
    partSegmentation.js             # 拆件、零件号与装配关系
    connectors.js                  # 定位销、榫槽、磁铁孔、胶合面
    baseAndBalance.js               # 底座、接地、重心与稳定性
    manufacturingManifest.js       # SKU/BOM/版本/校验和
    exporters/
      export3mf.js
      exportStl.js
  export/
    exportCharacterGlb.js          # 继续只负责数字角色
scripts/
  build-manufacturing-asset.mjs
  audit-manufacturing-mesh.py       # Blender/专用几何工具
  build-factory-package.mjs
tests/
  manufacturingProfile.test.mjs
  printAssembly.test.mjs
  manufacturingAudit.test.mjs
  factoryPackage.test.mjs
public/audit/manufacturing/
docs/manufacturing/
  PROCESS_PROFILES.md
  FACTORY_HANDOFF.md
  GOLDEN_SAMPLE_CHECKLIST.md
```

### 3.1 新的版本合同

每件数字或实体商品至少记录：

```json
{
  "tokenId": "414",
  "catTraitsSchemaVersion": 2,
  "generatorVersion": "3.0.0",
  "assetVersion": "1.0.0",
  "manufacturingProfile": "resin-figure-100mm-v1",
  "manufacturingPipelineVersion": "1.0.0",
  "sourceConfigHash": "sha256:...",
  "geometryHash": "sha256:...",
  "partRevision": "A",
  "supplierProfile": "supplier-id/profile-revision"
}
```

`CatTraits` 决定“这是谁”；`ManufacturingProfile` 决定“如何把它做成什么尺寸和工艺的实物”。两者不能混在一个 schema 中。

### 3.2 推荐的首个制造 Profile

先冻结一个简单 SKU，不要立即承诺 9,901 个 Token、任意形态、任意动作都可打印：

```text
resin-figure-100mm-v1
- 成品：约 100 mm 高的静态摆件
- 姿势：1 个冻结的制造安全姿势
- 工艺：高精度树脂打印原型/小批量
- 结构：猫主体 + 底座；复杂装备按规则拆件
- 颜色：首期单色打印 + 后处理喷涂，或供应商验证后的全彩 3MF
- 形态：只允许通过制造安全区间
- Special：首期排除，单独建立情景摆件 Profile
```

所有壁厚、间隙、孔径和细节阈值必须由具体工艺、材料、尺寸和供应商共同确定，不能写成全项目通用常数。

## 4. 商业化 Roadmap

时间是建议区间；阶段以验收门禁推进，而不是仅按日期推进。

### Phase 0 — 权利、商品和供应链冻结（第 0–4 周，P0）

目标：先确认“有权卖什么、卖给谁、由谁制造”。

工作：

- 由专业律师核对 Liberty Cats 商标、NFT 图片、metadata、3D 衍生品和持有者商业权利。
- 审计第三方代码、参考素材、字体、图片、动作视频和生成式内容许可。
- 定义商品模式：Token 持有者专属、公共定制、官方授权系列或混合模式。
- 选择首个工艺和供应商：建议先树脂打印，不直接开注塑模。
- 冻结首个 SKU 的高度、姿势、底座、装备范围、颜色方式、包装和目标售价。
- 要求供应商提供书面 DFM 参数和样件验收标准。

交付：

- 权利矩阵、第三方依赖 SBOM/许可清单。
- 商品 PRD、供应商 Profile、风险清单。
- `resin-figure-100mm-v1` 草案。

退出门禁：

- 商业授权无阻断项。
- 首个 SKU 与工厂能力书面确认。
- 未解决版权素材不得进入生产资产。

### Phase 1 — 冻结数字角色黄金基线（第 2–8 周，P0）

目标：让“数字角色正确”成为可签字的事实，而不只是测试通过。

工作：

- 对 44 个 Trait 完成正/侧/背和关键组合的人工视觉验收。
- 将 manifest 状态从 `pending-visual-verification` 转换为有审核人、日期和证据的状态。
- 建立 133 个代表 Token 的差异评分：轮廓、颜色、脸、装备、遮挡、比例。
- 为 2 个 Legendary/Special 定义角色版和场景版边界。
- 统一多份 Roadmap 的状态来源，废弃重复或过期的“下一步”列表。
- 恢复缺失的原始数据审计依赖，确保干净检出可完成全部测试。

退出门禁：

- 44/44 Trait 人工验收通过或存在有理由、有 owner 的例外。
- 代表集无未解释高优先级视觉差异。
- 干净环境测试、构建和数据审计全绿。

### Phase 2 — 制造数据合同与最小 Print Assembly（第 6–12 周，P0）

目标：生成第一份真正面向制造的、版本化的实体模型。

工作：

- 新增 `ManufacturingProfile` 和 `createPrintAssembly()`。
- 固定静态制造姿势，移除动画骨架、运行时辅助节点和场景。
- 将语义部件归类为：并入主体、独立零件、表面颜色、忽略。
- 对主体执行实体化和稳定布尔；删除封闭体内部无用几何。
- 生成底座和稳定连接。
- 实现毫米单位、目标高度和缩放记录。
- 输出 STL 作为兼容文件，3MF 作为首选制造包。

退出门禁：

- 一个基准 Token 可重复生成相同制造几何 hash。
- 所有输出零件具有明确单位、零件号和装配关系。
- 网格封闭、朝向一致、无非流形边、无退化面、无意外孤立壳体。

### Phase 3 — 自动 DFM 与制造门禁（第 10–18 周，P0）

目标：让不适合打印的组合在交厂前自动失败。

工作：

- 增加 watertight、manifold、自交、边界、法线和零体积检查。
- 增加供应商 Profile 驱动的壁厚、特征尺寸、间隙和孔径检查。
- 检查细尾巴、耳尖、手指、眼镜腿、杯柄、相机带等易断区域。
- 增加重心、底座接触、倾倒风险和包围盒检查。
- 树脂工艺增加空心化、排液孔、困液和支撑可达性检查。
- 输出 HTML/JSON DFM 报告和带问题标记的预览模型。
- 任何自动修复必须写入 manifest，禁止静默改变角色。

退出门禁：

- 基准集 100% 通过自动门禁。
- 人工注入的坏模型均能被对应规则阻止。
- 同一输入、Profile 和管线版本产生一致报告与 hash。

### Phase 4 — 配件、拆件和颜色生产体系（第 16–24 周，P1）

目标：从“一个能打印的猫”升级为“能装配、能涂装、能补件的商品”。

工作：

- 为 10 种装备分别冻结主体合并/拆件策略。
- 建立定位销、榫槽、磁吸、胶合面的参数化连接器。
- 设计防呆结构、装配方向和零件编号。
- 建立统一颜色 ID、材料 ID、Pantone/供应商色板映射和涂装区域图。
- 对全彩打印验证 3MF Materials/Properties；对手工涂装输出分色图和遮罩。
- 生成 BOM、爆炸图、装配说明和补件清单。

退出门禁：

- 10/10 装备有经实物验证的装配策略。
- 任一零件可从订单、Token、版本追溯并单独补发。
- 颜色样条和实体样件得到签字确认。

### Phase 5 — 实物打样与黄金样件（第 20–30 周，P0）

目标：用真实工艺关闭“屏幕正确但实物失败”的风险。

建议批次：

1. 基础 coupon：壁厚、柱径、孔径、间隙、纹理、颜色。
2. 5 个结构样件：无装备、头戴、手持、身体背负、细长配件。
3. 20–30 个代表 Token：覆盖 44 Trait 和形态边界。
4. 小批量 50–100 件：验证良率、装配、包装和物流。

每轮记录：

- 打印成功率、破损率、尺寸偏差、装配间隙、表面缺陷、颜色偏差。
- 单件材料、机器、后处理、人工、返工、包装和物流成本。
- 工厂修改项、生成器版本、供应商 Profile 和样件照片。

退出门禁：

- 黄金样件由产品、艺术、结构和供应商共同签字。
- 小批量良率、返工率和毛利达到业务阈值。
- 包装运输测试没有系统性断件或磨损问题。

### Phase 6 — 订单与生产平台（第 24–36 周，P1）

目标：把一次性脚本变成可运营、可审计的商业系统。

工作：

- 登录、Token 所有权/授权验证、订单、支付和退款。
- 服务端生成队列，禁止把完整高价值制造模型只放在浏览器端生成。
- 资产对象存储、CDN、签名下载、保留周期和删除策略。
- 订单状态机：草稿→付款→生成→自动 DFM→人工复核→冻结→交厂→质检→发货。
- 生产冻结后禁止配置漂移；修改必须创建新 revision。
- 管理后台处理人工复核、例外、返工、补件和召回。
- 监控生成失败率、队列延迟、单位成本、良率和售后原因。

退出门禁：

- 每个实体订单能追溯到源配置、代码/资产版本、制造 Profile、供应商批次和交付文件 hash。
- 失败订单不会进入工厂队列。
- 权限、支付、隐私、备份和灾难恢复通过上线审查。

### Phase 7 — 9,901 全量制造覆盖（第 32–44 周，P1）

目标：从有限 SKU 扩展到全量 Token，但不承诺每个任意编辑组合都天然可制造。

工作：

- 对 9,901 Token 执行制造装配和 DFM 审计。
- 按失败原因聚类，不逐 Token 手工打补丁。
- 建立 manufacturing-safe morphology 范围。
- 对异常 Token 使用版本化、可解释的例外配方。
- 对每个 Trait 簇至少打印一个代表实物。
- 将全量审计摘要作为发布门禁和版本产物。

目标指标：

```text
9901 normalized
9901 print assemblies generated
9901 manufacturing profiles resolved
0 unknown units
0 non-manifold production parts
0 untracked geometry repairs
0 unexplained DFM exceptions
100% factory packages reproducible by hash
```

### Phase 8 — 注塑/搪胶等量产 DFM（销售验证后，P2）

目标：只在 SKU 和销量已验证后进入模具投入。

重要原则：打印模型不能直接作为注塑模型。

工作：

- 重新设计均匀壁厚、抽壳、圆角、拔模角和分型线。
- 处理倒扣、滑块、镶件、浇口、顶针、排气、缩水和熔接线。
- 根据材料收缩率和表面纹理重新标定尺寸。
- 将角色拆为适合模具数量、喷涂和装配的标准件。
- 进行 Moldflow/供应商 DFM、T0/T1/T2 试模、颜色和表面签样。
- 建立模具所有权、寿命、维护、备件和跨工厂转移条款。

退出门禁：

- 模具 DFM、试模、可靠性、法规、包装和量产 QA 全部签字。
- 单位经济模型覆盖模具摊销、损耗、仓储和售后。

## 5. 优先级建议

### P0：现在必须做

1. 权利与商业许可审计。
2. 选择首个工艺、工厂和单一 SKU。
3. 完成 44 Trait 人工视觉验收。
4. 建立 `ManufacturingProfile` 和 Print Assembly。
5. 建立制造网格与 DFM 门禁。
6. 打印 coupon、代表样件和黄金样件。
7. 补齐干净环境下缺失的原始数据测试依赖。

### P1：样件通过后

1. 10 种装备拆件与连接结构。
2. 颜色、材料、BOM、装配和补件体系。
3. 服务端生产队列、订单与工厂交付包。
4. 9,901 Token 全量制造审计。
5. 商业前端、账号、支付、客服和可观测性。

### P2：有真实销量后

1. 注塑/搪胶量产结构重建与开模。
2. 游戏和跨平台 Runtime 产品化。
3. AR、数字藏品联动、UGC 商店和第三方 SDK。
4. 多供应商和跨地区制造。

```text

├─ preview/
│  ├─ approved-front.png
```

## 7. 发布与质量门禁

### 数字角色门禁

- CatTraits 合法且可迁移。
- 相同输入可复现。
- GLB 可回读，metadata、骨架和目标动画完整。
- 代表集视觉审核通过。

### 制造资产门禁

- 明确使用毫米或 Profile 定义的单位。
- 每个生产零件封闭、可定向、无非流形和意外壳体。
- 通过供应商 Profile 的壁厚、特征、间隙和稳定性检查。
- 拆件、BOM、颜色和装配关系完整。
- 自动修复和人工修改全部可追溯。
- 生成 hash 与冻结订单一致。

### 商业订单门禁

- 权利和用户授权有效。
- 付款、退款、隐私和生产条款清晰。
- 订单配置已冻结并由用户确认预览。
- DFM 自动通过且高风险订单完成人工复核。
- 工厂回传批次和质检记录。

## 8. 关键指标

产品指标：

- 配置到批准预览的完成率。
- 首次生成成功率和平均生成时间。
- 预览确认后的修改率。
- 退款率、投诉率和复购率。

制造指标：

- 自动 DFM 首次通过率。
- 样件/量产良率、返工率和报废率。
- 断件、装配、颜色和表面缺陷占比。
- 单件总成本、人工时间和交付周期。
- 工厂包 hash 可复现率。

质量指标：

- 44 Trait 人工通过率。
- 9,901 Token 制造装配通过率。
- 未解释视觉/DFM 例外数量。
- 同配置跨版本差异和迁移成功率。

## 9. 近期 30 天执行清单

第 1 周：

- 冻结首个 SKU 假设和候选供应商。
- 开始法律/许可审计。
- 建立 44 Trait 人工验收表，指定艺术审核 owner。
- 将现有 Roadmap 标记为历史/领域文档，指定本文件为商业化状态入口。

第 2 周：

- 从 133 个代表 Token 中选择首批 20–30 个制造验证集。
- 与工厂确认 resin profile、材料、尺寸和 DFM 阈值。
- 设计 `ManufacturingProfile` schema 和版本策略。
- 选择 Blender 加专用网格库，或其他可自动化实体几何方案并做技术 spike。

第 3 周：

- 完成一个无装备基准 Token 的 Print Assembly。
- 输出有明确毫米单位的 3MF/STL。
- 加入封闭性、非流形、自交和孤立壳体检查。
- 设计基础底座并验证重心。

第 4 周：

- 打印第一轮尺寸/间隙 coupon 和 3–5 个基准样件。
- 记录工厂反馈并冻结 `resin-figure-100mm-v1`。
- 建立黄金样件 checklist。
- 根据实物结果决定下一轮装备拆件顺序。

## 11. 决策原则

1. `CatTraits` 是角色事实源，但不是制造说明书。
2. 数字网格、渲染网格和制造网格同源但不共用验收标准。
3. 所有制造阈值属于版本化的工艺/供应商 Profile。
4. 自动修复不得静默改变角色；任何例外必须可解释、可追溯。
5. 先做一个 SKU 的闭环，再扩展到 44 Trait 和 9,901 Token。
6. 先树脂打印验证造型和需求，再根据销量决定是否开模。
7. 工厂交付必须包含版本、单位、BOM、批准预览和 hash，而不只是网格文件。
8. 法律授权、视觉验收、DFM 和实物样件四个门禁缺一不可。
