# Liberty Cat Studio 测试计划

> 适用版本：Web 参数化 3D 猫生成器 3.x  
> 测试对象：Vue 3 编辑器、Three.js 角色与场景、9,901 Token 图鉴、CatTraits 参数系统、2D/3D 对照、PNG/GLB/角色卡导出。  
> 关联文档：[设计哲学](./DESIGN_PHILOSOPHY.md)、[开发路线图](./DEVELOPMENT_ROADMAP.md)、[视觉基线](./baselines/README.md)。

## 1. 测试目标

测试不仅确认“按钮能否点击”，还要验证以下产品承诺：

1. 同一份 `CatTraits` 能稳定驱动预览、分享和导出。
2. 44 个 metadata Trait 均有明确、可追溯的程序化表现。
3. 9,901 个有效 Token 均可载入、复现和审计。
4. 用户可以快速发现、编辑、验证并带走一只猫。
5. 桌面端、移动端、键盘和触摸设备都有完整操作路径。
6. 体型极值、装备切换、Special 场景和导出过程不会破坏模型或泄漏资源。

核心体验验收句：**让用户先看到角色，再理解参数，最后可信地导出结果。**

## 2. 测试范围

### 2.1 范围内

- 首次加载、Seed 和 URL 参数恢复。
- 随机生成、Token 载入、相邻 Token、图鉴筛选。
- 体型、毛色、眼睛、表情、装备、背景、Special、IP、动作。
- 参数锁定、撤销、重做与恢复默认值。
- 创作模式、验证模式与 2D/3D 对照。
- 固定视角、鼠标/触摸相机操作、键盘和虚拟移动。
- 天气、灯光、画质模式和特殊场景。
- PNG、透明头像、社交头像、三视图、SVG 角色卡、JSON、分享链接和 GLB。
- Three.js 生命周期、资源销毁、性能预算与 WebGL 恢复。
- 9,901 Token 数据完整性和程序化审计产物。
- 响应式、可访问性、信息层级和可理解性。

### 2.2 当前不作为通过条件

- 区块链写入、钱包连接和链上铸造。
- 服务端账户、云同步和多人协作。
- Blender、Unity、Unreal 中所有版本的完全一致渲染。
- SVG 审计缩略图与真实 WebGL 渲染画面的像素级一致；SVG 仅用于数据审计定位。
- 中文、日文、英文按钮目前仅切换语言状态，若尚未接入完整文案资源，不应报告为完整国际化通过。

## 6. 用户体验测试

### 6.1 参与者建议

每轮至少 8–12 人：

- 2–3 名普通访客：没有 3D 或 NFT 背景。
- 2–3 名角色创作者：熟悉捏脸、换装或游戏编辑器。
- 2–3 名 Liberty Cats 收藏者：关注 Token 和原图还原。
- 1–2 名 3D/游戏开发者：关注模型、动作和 GLB。

主持人不演示页面，只提供任务。要求参与者边操作边说出判断依据。

### 6.2 核心任务

| ID | 用户任务 | 成功标准 | 目标指标 |
|---|---|---|---|
| UX-001 | “生成一只你喜欢的猫并保存图片” | 独立找到随机、编辑和 PNG | 90% 成功；中位时间 ≤30 秒 |
| UX-002 | “找到 #414，并判断 3D 是否像原图” | 成功载入并打开对照 | 85% 成功；≤3 个主要动作 |
| UX-003 | “把猫变胖、尾巴变长，但随机时保留两项” | 正确调整并锁定后随机 | 80% 成功；无主持人帮助 |
| UX-004 | “给猫换装备并切到背面检查” | 找到装备和固定背面视角 | 90% 成功 |
| UX-005 | “为什么背景不能改？恢复普通背景” | 理解 Special 覆盖并恢复 | 85% 能正确解释原因 |
| UX-006 | “撤销刚才的错误修改” | 一次撤销恢复预期结果 | 95% 成功 |
| UX-007 | “导出一个可交给 3D 软件的文件” | 找到 GLB 并理解导出状态 | 80% 成功 |
| UX-008 | “在手机上单手换毛色并保存” | 抽屉和主按钮可触达，猫仍可见 | 85% 成功；无误触中断 |

### 6.3 体验观察点

- 首次注意力是否先落在猫，而不是参数面板。
- 用户是否理解“创作”和“验证”的差异。
- 用户能否预测调整一个参数后会发生什么。
- 是否误把天气、背景和 Special 当成同一层功能。
- 参数被禁用时，用户能否找到原因和恢复动作。
- 输出菜单是否降低了选择负担，还是让功能变得难找。
- 移动端打开抽屉时，猫的头、脸和装备是否仍可见。
- 用户是否相信导出内容与当前预览来自同一配置。

### 6.4 主观量表

任务结束后采用 1–7 分量表：

1. 我能快速找到想修改的部位。
2. 修改后，我能立刻理解发生了什么。
3. 出错时，我知道如何恢复。
4. 我能确认这只 3D 猫来自哪个 Token。
5. 界面没有遮挡我最关心的角色部分。
6. 我相信保存或导出的结果与预览一致。
7. 我愿意继续探索或制作更多角色。

单项平均分应不低于 5；第 2、3、6 项属于关键可信度指标，应不低于 5.5。

## 7. UI、响应式与视觉测试

### 7.1 桌面布局

- 左侧图鉴/证据、中央角色、右侧配置、底部输出边界清晰。
- 同时只展开一个主要任务面板时，不遮挡猫的脸和主要装备。
- 右侧面板滚动不带动页面或相机。
- 黄色强调色主要用于当前选择和主操作，同屏不出现大量同权主按钮。
- 正文和按钮可读，不因中、日、英文本长度改变关键布局。

### 7.2 移动布局

- 配置器从底部进入，最大高度不超过约 68vh。
- 抽屉关闭后虚拟移动控制可用；打开后不与参数控件重叠。
- 主要触摸目标至少 44×44 CSS px。
- 底部导出栏、系统安全区和浏览器工具栏之间无重叠。
- 390×844 基线下角色保留足够可视面积。

### 7.3 视觉回归

固定使用 Seed 414 生成：

- 桌面正面、侧面、背面。
- 桌面 3/4 视角。
- 移动端 390×844，配置器展开和关闭各一张。
- 默认体型及六项体型极值。
- 所有装备、Eyes × Face 代表组合和七种 Special。

允许差异：抗锯齿、GPU 浮点误差和轻微阴影噪声。不可接受差异：肢体脱节、尾根悬空、挂点漂移、脸部组件错位、角色被裁切、面板遮住主要特征。

## 9. 3D、性能与稳定性测试

### 9.1 模型质量

- 默认和所有极值体型包围盒均为有限数值。
- 肩、髋、手掌、脚掌和尾根与身体保持合理嵌入。
- 四视角中正面脚垫不误显，背面脚垫可见。
- 动作切换后骨骼能回到规范姿势。
- 装备只通过 registry socket 访问角色挂点。

### 9.2 性能指标

| 指标 | 建议通过线 |
|---|---|
| 首次可交互 | 常规桌面网络环境 ≤3 秒；本地资源 ≤1.5 秒 |
| 参数反馈 | 普通 Trait 变化可见反馈 ≤100ms |
| 相机与动画 | 桌面目标 60 FPS；低性能模式稳定 ≥30 FPS |
| 长时运行 | 连续运行 30 分钟无崩溃、明显卡顿累积 |
| 装备切换 | 100 次切换后对象和纹理数量趋于稳定 |
| Token 连续浏览 | 连续载入 200 个 Token 无持续显著内存增长 |
| GLB 导出 | 默认角色应在合理时间完成，并提供真实阶段反馈 |

### 9.3 异常恢复

- 页面切到后台后暂停不必要渲染，返回后恢复。
- WebGL context lost 被阻止默认行为并可安全恢复。
- ResizeObserver、事件监听、天气、Special 和装备资源在销毁时清理。
- 快速切换 Special 时旧异步请求不得覆盖最新选择。
- 远程原图失败不影响 3D 编辑和导出。

## 10. 9,901 Token 与 Trait 审计

全量审计必须确认：

1. 有效 Token 数为 9,901，排除项与产品范围一致。
2. 每个 Token 都能规范化为合法 `CatTraits`。
3. 44 个 metadata Trait 都在 manifest、运行时枚举和属性文档中双向一致。
4. `null` 表示缺失或由完整 Special 接管，不得用猜测值填充。
5. 每个 Token 有 JSONL 记录和审计缩略图；缩略图只是索引，不宣称是真实 WebGL 渲染。
6. 代表性样本必须配对原始 2D 证据和固定多视角 3D 检查。
7. 未知 Trait、缺图、fallback、部分实现和冲突规则都进入报告，不静默忽略。

建议人工抽检：每种 Trait 至少 3 个 Token；稀有 Trait 和完整 Special 全检；体型和装备的组合边界额外抽检。

## 11. 缺陷分级

| 等级 | 定义 | 示例 |
|---|---|---|
| P0 阻断 | 核心数据错误、崩溃、结果不可恢复或导出错误 | Token/Trait 错配、GLB 无角色、随机破坏锁定值 |
| P1 严重 | 主流程可继续但关键能力失真 | 肢体脱节、装备挂点漂移、无法撤销、移动端主要按钮不可用 |
| P2 一般 | 存在替代路径或局部体验问题 | 提示不清、次级布局重叠、状态文案不一致 |
| P3 轻微 | 不影响任务完成的视觉或文案问题 | 轻微间距、非关键动画、标点问题 |

缺陷记录至少包含：版本/commit、环境、Token/Seed、前置条件、复现步骤、实际结果、预期结果、截图或视频、控制台信息、严重级别。

## 12. 发布门禁

发布候选版本必须同时满足：

- 全部自动化测试和生产构建通过。
- 无未关闭 P0、P1 缺陷。
- P2 缺陷有明确接受人和后续版本计划。
- Seed 414 桌面/移动视觉基线已人工确认。
- 默认体型和体型极值无肢体、尾巴脱节。
- 10 种装备、7 种 Special、固定四视角和主要导出路径通过。
- 至少完成一次键盘、触摸、200% 缩放和 reduced-motion 验收。
- 9,901 Token 全量数据审计为零未知、零非法记录。
- PNG、分享链接、JSON 与 GLB 均使用当前同一份 CatTraits。
- 已知限制写入发布说明，不把审计 SVG 描述为真实 3D 渲染结果。
