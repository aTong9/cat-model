如果未来要让导出的猫从当前场景直接走出去进入小游戏，我不建议把另外三面做成三个互不
  相关的平面背景。更合适的是把“时空旅人”做成一个连续、可探索的四区时空枢纽。

  推荐布局：

   左侧    一望无际的草原    新手跑酷：跳跃、收集金币、低矮障碍
  ──────  ────────────────  ────────────────────────────────────
   右侧    广袤海洋与岛屿    水上跑酷：浮台、冲浪、移动船只
  ──────  ────────────────  ────────────────────────────────────
   背面    浩瀚星空          高难关卡：低重力、漂浮平台、传送门

  关键不是把四张景色拼在一起，而是用“时空裂隙”连接四个区域。中心区域保持现在的合成波
  网格广场，三个方向各放一座立体传送门。透过传送门可以看见草原、海洋和宇宙；进入后再
  加载对应关卡。这样既符合“时空旅人”主题，也避免相机旋转后突然看到贴图边缘。

  建议的世界结构：

                      星空裂隙
                         │
  草原裂隙 ─── 霓虹时空广场 ─── 海洋裂隙
                         │
                    未来城市远景

  技术上建议现在就按游戏场景标准设计：
  - 猫 GLB 包含骨骼、动画和装备挂点，不捆绑天空与城市。
  - 场景增加 spawn、exit、checkpoint、collectible 等命名节点。
  - 所有地面设置可行走碰撞体。
  - 传送门设置触发范围和目标关卡 ID。
  - 远景使用低成本模型，实际关卡进入后再动态加载。
  - 相机旋转范围放开后，四个方向始终有合理内容。
  - 第一版小游戏优先做无尽跑酷，和当前模型系统最匹配。

  跑酷是很好的第一种玩法，因为现有功能几乎都能复用：

  - 毛色、眼睛和表情成为外观。
  - 装备可以提供技能或数值加成。
  - 天气成为关卡规则。
  - 特殊场景成为不同跑酷世界。
  - 导出的 GLB 可以直接作为玩家角色。
  - NFT 式 trait 数据可以直接转成游戏角色配置。

  我建议下一阶段先做“四面可见，但只有一面可进入”的最小版本：

  1. 补齐草原、海洋、星空三个立体远景。
  2. 在三个方向建立时空传送门。
  3. 先开放草原入口，制作一条短跑酷测试路线。
  4. 给猫增加待机、奔跑、跳跃、落地四套动画。
  5. 验证当前 GLB 能否作为独立玩家角色加载。

  这比一次性制作四个完整世界风险低，也能最快证明“生成猫 → 导出 GLB → 进入游戏”的完整
  闭环。
